Decision Guide

When to use instructions, skills, or agents.

Most confusion comes from using the right concept at the wrong level. This guide gives a simple selection rule: use the lightest mechanism that solves the problem cleanly.

Open parent concept Read quickstart See worked example
Instructions

Use for always-on rules

Choose instructions when the behavior should apply to every request, regardless of task or role.

  • Coding standards and naming rules
  • Testing expectations
  • Documentation conventions
If you would be annoyed repeating the same rule every time, it belongs in instructions.
Skills

Use for repeatable workflows

Choose skills when a task has a stable sequence, clear inputs, and a predictable output format.

  • Bug triage
  • API review
  • Migration planning
If the same multi-step task shows up across teams, it should become a skill.
Agents

Use for specialized roles

Choose agents when the work needs a distinct persona, tools, permissions, or inherited behavior bundle.

  • API architect
  • SRE debugger
  • Security reviewer
If the role needs a different operating posture, create an agent instead of piling more rules into one assistant.

Simple selection flow

1. Does this need to apply to nearly every request? Use instructions.
2. Is this a repeatable task with known steps and outputs? Use a skill.
3. Does this work require different tools, permissions, or review posture? Use an agent.
4. If two options seem plausible, choose the smaller one first and upgrade only when the behavior stops fitting.

Common anti-patterns

  • Using an agent for something that is only a checklist.
  • Stuffing reusable task logic into instructions instead of a skill.
  • Writing giant instructions files that become impossible to maintain.
  • Creating too many agents before one good shared skill library exists.
