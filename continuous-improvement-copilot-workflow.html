Workflow Setup

Add Continuous Improvement to your Copilot workflow.

This page shows how to make process improvement a required step after every enhancement: run a short retrospective, update one process artifact, and include a structured handoff record so lessons are never lost.

instructions guide skills example agents example

Setup steps

1) Add an explicit CI rule to instructions.

In .github/copilot-instructions.md, require one process improvement after each enhancement and mark completion as blocked until retrospective output is included.

2) Add a workflow step to skills.

In .github/skills.md, include a required retrospective step at the end of the new-page workflow so improvement is part of execution, not optional cleanup.

3) Add output requirements to agents.

In .github/agents.md, require the agent to include a short retrospective record in every final handoff message.

4) Add quality gate in APM.

In apm.yml, add a retrospective-update quality gate so the governance manifest checks this behavior before publish.

Why this works: by connecting instructions + skills + agents + APM, the same improvement behavior is enforced at policy, workflow, role, and release-gate layers.

Required handoff template

Retrospective Record (Required)

1. What slowed us down?
2. What process/file is being improved?
3. Exact rule added or changed.
4. How this prevents repeat issues.
Good retrospective update
  • Identifies a concrete friction point from the latest change.
  • Updates one specific rule in one process file.
  • Explains how the new rule prevents recurrence.
Common mistakes
  • Generic statements with no rule change.
  • Adding broad policy rewrites instead of one targeted fix.
  • Skipping the final handoff record.
